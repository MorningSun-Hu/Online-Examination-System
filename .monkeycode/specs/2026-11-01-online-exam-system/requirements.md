# Requirements Document

## Introduction

本规格描述一套面向教室场景的在线考试系统：教师机运行服务端，教师与学生均通过网页操作。教师可维护题库、导入符合《题库格式化规范》的 HTML、导入学生、按规则自动组卷、发布考试或练习、控制提前交卷、自动批改客观题、公开试卷并回发到学生机、导出成绩并进行分析。

本阶段范围覆盖客观题全流程与编程题入库、作答、人工给分。在线编译评测不在本阶段范围。部署默认形态为教室局域网内一台教师机作为唯一服务端。

## Glossary

- **教师机**：运行本系统服务端的计算机，同时提供教师网页与学生网页。
- **学生机**：学生用来打开学生网页并作答的计算机。
- **教师**：在教师网页上管理题库、学生、考试任务、批改与成绩的操作者。
- **学生**：在学生网页上进入考试或练习并提交答卷的作答者。
- **题库**：一组结构化题目的集合，可来自手工创建或 HTML 导入。
- **题目**：题库中的一条试题，含题干、题型、选项（如有）、参考答案、来源与分值元数据。
- **客观题**：单选题、多选题、判断题、填空题，系统可按参考答案自动判分。
- **主观题**：编程题，本阶段由教师人工给分。
- **考试任务**：一次正式测评活动，含组卷规则、学生名单、时长、交卷策略与模式。
- **练习任务**：允许重复作答、提交后立即反馈对错与分数的活动。
- **组卷规则**：题型选择、各题型题量、选项是否随机、大题内小题是否随机、分项分值、总分及分值自动调整策略。
- **试卷快照**：按组卷规则为某次作答生成的题目集合、顺序、选项映射与分值表，批改以该快照为准。
- **当场会话**：学生机浏览器在本次打开学生网页期间建立的客户端标识与在线连接。
- **学生匹配**：用班级，再加姓名或学号（至少一项），在当前任务名单中解析到唯一学生记录。
- **历史提交**：已提交但当场会话已结束的答卷，再次进入时用学生匹配解析到同一学生记录后领取。
- **公开试卷**：教师完成批改后将成绩与批改详情对学生可见的动作。
- **提前交卷**：考试结束时刻之前由学生主动提交答卷。
- **题库格式化规范**：用户提供的 HTML 题库文档约定，含 UTF-8、黑白试卷结构、`.question` / `.options` / `.answer` 等标记。

## Requirements

### Requirement 1: 题库创建与维护

**User Story:** AS 教师, I want 创建并维护题库与题目, so that 后续组卷有稳定的题目来源。

#### Acceptance Criteria

1. WHEN 教师创建题库并填写名称, THE 系统 SHALL 保存该题库并在题库列表中展示名称、题目数量与更新时间。
2. WHEN 教师在指定题库中新增题目, THE 系统 SHALL 要求选择题型（单选题、多选题、判断题、填空题、编程题）并保存题干、选项（选择题）、参考答案、来源说明。
3. WHEN 教师编辑或删除题库中尚未被已发布考试任务引用的题目, THE 系统 SHALL 按教师确认结果更新该题库。
4. IF 目标题目已被至少一份已发布考试任务的试卷快照引用, THE 系统 SHALL 拒绝删除该题目，并提示教师该题目已被考试任务引用。

### Requirement 2: HTML 题库导入解析

**User Story:** AS 教师, I want 按题库格式化规范导入 HTML 题库, so that 已有试卷文档可以进入系统组卷。

#### Acceptance Criteria

1. WHEN 教师上传 UTF-8 编码且符合题库格式化规范的 HTML 文件, THE 系统 SHALL 解析文档标题、试卷标题（`h2`）、题型标题（`h3`）、每道 `.question` 的题干、代码块、选项、答案与来源，并写入指定题库。
2. WHEN 解析器识别题型标题含「选择题」「判断题」「填空题」「编程题」, THE 系统 SHALL 将对应题目分别归入单选题或多选题、判断题、填空题、编程题。
3. WHEN 选择题答案字段为单个字母, THE 系统 SHALL 将该题保存为单选题。
4. WHEN 选择题答案字段含两个或以上选项字母, THE 系统 SHALL 将该题保存为多选题。
5. WHEN HTML 文件无法按题库格式化规范解析出至少一道题目, THE 系统 SHALL 拒绝写入题库，并返回文件名、失败原因与失败位置（题号或 HTML 片段摘要）。
6. WHEN 部分题目解析成功且部分题目失败, THE 系统 SHALL 写入成功题目，并生成导入报告，列出成功数量、失败数量、每条失败的题号与原因。

### Requirement 3: 题库导出与往返一致性

**User Story:** AS 教师, I want 把题库再导出为规范 HTML, so that 题库可以打印、备份并再次导入。

#### Acceptance Criteria

1. WHEN 教师导出指定题库, THE 系统 SHALL 生成符合题库格式化规范的 HTML 文档，包含 UTF-8、`lang="zh-CN"`、黑白样式、`.question` / `.options` / `.answer` 结构。
2. WHEN 系统将内存中的题目集合序列化为规范 HTML 后再解析, THE 解析结果 SHALL 在题型、题干纯文本、选项文本、参考答案、来源字段上与序列化前一致。
3. WHEN 导出 HTML, THE 系统 SHALL 使用题库格式化规范中的标题层级：文档标题为 `h1`，试卷或分组标题为 `h2`，题型标题为 `h3`。

### Requirement 4: 学生名册导入

**User Story:** AS 教师, I want 导入含班级、学号、姓名的学生名单, so that 学生可用班级加姓名或学号进入。

#### Acceptance Criteria

1. WHEN 教师导入 UTF-8 CSV 学生名册且表头含「班级」「学号」「姓名」, THE 系统 SHALL 为每一行创建或更新学生记录。
2. WHEN 两行学号相同, THE 系统 SHALL 用后导入行覆盖同名册中该学号的姓名与班级。
3. IF 某一行缺少班级、学号或姓名, THE 系统 SHALL 跳过该行，并在导入报告中记录行号与原因。
4. WHEN 教师将学生加入某考试任务, THE 系统 SHALL 仅允许从已导入名册中选择学生。

### Requirement 5: 组卷规则与自动组卷

**User Story:** AS 教师, I want 按规则从题库自动组卷, so that 可以控制题型、题量、乱序与分值。

#### Acceptance Criteria

1. WHEN 教师创建组卷规则, THE 系统 SHALL 允许选择一个或多个题库、选择包含的题型、为每种题型指定抽取数量。
2. WHEN 组卷规则启用「大题内小题顺序随机」, THE 系统 SHALL 在同一题型分组内随机排列小题顺序，并保持题型分组之间的相对顺序。
3. WHEN 组卷规则启用「选项随机」, THE 系统 SHALL 对单选题与多选题的选项顺序随机排列，并保存选项字母到原选项的映射，使参考答案仍指向原正确选项。
4. WHEN 某题型在所选题库中的可用题目数量小于规则要求数量, THE 系统 SHALL 拒绝生成试卷快照，并提示该题型现有数量与要求数量。
5. WHEN 教师确认组卷, THE 系统 SHALL 为后续每一次作答生成独立的试卷快照，快照含题目标识、题型内顺序、选项映射与每题分值。

### Requirement 6: 分项分值、总分与自动调分

**User Story:** AS 教师, I want 设置各题型分值与总分并由系统自动调齐, so that 卷面分值加总等于设定总分。

#### Acceptance Criteria

1. WHEN 教师设置考试总分 T 且 T 为正整数, THE 系统 SHALL 将该总分作为卷面满分保存到组卷规则。
2. WHEN 教师为某一题型设置分项小计, THE 系统 SHALL 把该题型小计按题量分配到各小题：每题先得整数商，余数加在该题型最后若干小题，每题加 1 分，直到余数分配完毕。
3. WHEN 教师只设置总分与各题型题量、未设置分项小计, THE 系统 SHALL 把总分按全部小题数量做同样的整数分配，余数按题型顺序再按题号顺序每次加 1 分。
4. WHEN 各题型分项小计之和与总分不一致, THE 系统 SHALL 按各分项小计占当前小计之和的比例缩放到总分，四舍五入到整数后再用余数或缺口按题型顺序微调，使各题分值均为正整数且总和等于总分。
5. WHEN 自动调分完成, THE 系统 SHALL 向教师在试卷预览中展示每题分值，并在教师确认或内联修改后写入该试卷的分值方案。

### Requirement 7: 考试任务与练习任务

**User Story:** AS 教师, I want 创建考试任务或练习任务并发布, so that 学生可以按不同模式作答。

#### Acceptance Criteria

1. WHEN 教师创建任务, THE 系统 SHALL 要求选择模式（考试或练习）、已组试卷、参与班级或学生、作答时长（正整数分钟）以及是否允许提前交卷。
2. WHEN 教师发布考试任务, THE 系统 SHALL 将任务状态切换为「已发布」，并向学生网页提供进入入口。
3. WHILE 任务处于已发布状态且当前时刻未超过结束时刻, THE 系统 SHALL 允许名单内学生进入该任务作答。
4. WHEN 教师结束已发布任务, THE 系统 SHALL 将任务状态切换为「已收卷」，并拒绝新的作答进入。

### Requirement 8: 学生进入与当场会话

**User Story:** AS 学生, I want 用班级再加姓名或学号在学生机进入已发布任务, so that 答卷可以绑定到本人和当前计算机。

#### Acceptance Criteria

1. WHEN 学生提交学号或姓名中的至少一项，且学生匹配在当前任务名单（空名单则全库）中命中恰好一名学生, THE 系统 SHALL 建立当场会话，保存该学生记录与学生机客户端标识。
2. IF 学生匹配在当前已发布任务名单中命中零名学生, THE 系统 SHALL 拒绝进入，并提示名单中无此学生。
3. IF 学生仅提供班级与姓名且该组合在当前任务名单中命中两名或以上学生, THE 系统 SHALL 拒绝进入，并提示重名、请改填学号。
4. IF 学生同时提供班级、学号与姓名且学号命中的记录姓名与提交姓名不一致, THE 系统 SHALL 拒绝进入，并提示姓名与学号不匹配。
5. WHEN 同一学生记录已有未提交的当场会话来自另一客户端标识, THE 系统 SHALL 将后续作答连接到最新一次通过校验的客户端标识，并继续使用已保存的试卷快照与已答内容。
6. WHEN 教师网页打开接入页, THE 系统 SHALL 展示学生可访问的本机局域网地址列表。

### Requirement 9: 考试模式作答

**User Story:** AS 学生, I want 在考试模式中完成并提交试卷, so that 教师机能收到一次正式答卷。

#### Acceptance Criteria

1. WHILE 学生处于考试模式未提交状态, THE 系统 SHALL 向学生网页提供试卷快照中的题干、选项与作答控件，并省略参考答案与得分字段。
2. WHILE 考试任务允许提前交卷且学生尚未提交, THE 系统 SHALL 提供提交控件。
3. WHILE 考试任务禁止提前交卷且当前时刻早于结束时刻, THE 系统 SHALL 仅提供保存作答内容的能力，提交控件保持不可用。
4. WHEN 考试结束时刻到达且学生仍有未提交答卷, THE 系统 SHALL 使用已保存作答内容生成提交记录。
5. WHEN 考试模式答卷提交成功, THE 系统 SHALL 向该学生网页展示「已提交」状态，并省略分数、参考答案与逐题对错。
6. IF 该学生在该考试任务下已存在提交记录, THE 系统 SHALL 拒绝再次提交。

### Requirement 10: 练习模式作答

**User Story:** AS 学生, I want 在练习模式中反复作答并立刻看到对错, so that 可以用来复习。

#### Acceptance Criteria

1. WHEN 学生在练习模式提交一次作答, THE 系统 SHALL 立即展示本次得分、每题对错与参考答案。
2. WHEN 学生在同一练习任务下再次进入, THE 系统 SHALL 允许开始新的一次作答；每次作答使用按组卷规则新生成的试卷快照。
3. WHEN 练习任务禁止提前交卷, THE 系统 SHALL 在结束时刻之前按考试任务相同规则限制主动提交，并在结束时刻使用已保存内容生成该次练习提交。

### Requirement 11: 断线续答

**User Story:** AS 学生, I want 网络中断后还能继续未交卷的考试, so that 已填写内容不会丢失。

#### Acceptance Criteria

1. WHEN 学生在未提交状态下修改答案, THE 系统 SHALL 将已答内容保存到教师机，保存间隔不超过 15 秒。
2. WHEN 同一学生记录与客户端标识在任务结束前重新进入未提交的考试, THE 系统 SHALL 恢复原试卷快照与已保存答案。

### Requirement 12: 自动批改与人工给分

**User Story:** AS 教师, I want 客观题自动出分、编程题可手工给分, so that 收卷后尽快得到成绩。

#### Acceptance Criteria

1. WHEN 考试或练习提交到达教师机, THE 系统 SHALL 对单选题、多选题、判断题按试卷快照中的参考答案与选项映射自动判分。
2. WHEN 填空题作答与参考答案比较, THE 系统 SHALL 先去除首尾空白，再将全角字符转为半角，再比较；参考答案含多条（以 `|` 分隔）时，任一匹配即判为该空正确。
3. WHEN 多选题的学生所选集合与正确选项集合完全相同, THE 系统 SHALL 将该题记为满分；所选集合与正确集合不同时记为零分。
4. WHEN 提交中含编程题, THE 系统 SHALL 将该题标记为待人工给分，客观题分数仍立即累计。
5. WHEN 教师为某学生的编程题录入 0 到该题满分之间的整数分, THE 系统 SHALL 更新该生总分。
6. WHEN 任务下全部提交的客观题均已自动批改, THE 系统 SHALL 将任务状态切换为「已批改」；仍有待人工给分的编程题时，教师可在给分完成后确认批改完成。

### Requirement 13: 公开试卷与回发学生机

**User Story:** AS 教师, I want 批改完成后公开试卷并回发到学生, so that 学生能看到自己的批改结果。

#### Acceptance Criteria

1. WHEN 教师对已批改任务执行公开试卷, THE 系统 SHALL 将任务状态切换为「已公开」，并使该任务下每份提交的得分、逐题对错、参考答案、选择题选项与教师评语对学生可见。
2. WHEN 公开试卷时目标学生的当场会话仍在线, THE 系统 SHALL 把该学生的批改结果投递到产生该提交的客户端标识对应的学生网页。
3. WHEN 公开试卷时目标学生的当场会话不在线, THE 系统 SHALL 将批改结果归档到该学生记录；该学生后续用学生匹配进入学生网页时，系统展示该记录下已公开的试卷。
4. WHILE 任务尚未公开, THE 考试模式学生网页 SHALL 仅展示已提交或作答中状态。

### Requirement 14: 成绩获取、导出与分析

**User Story:** AS 教师, I want 查看、导出并分析成绩, so that 可以掌握班级与逐题表现。

#### Acceptance Criteria

1. WHEN 教师打开已批改或已公开任务的成绩页, THE 系统 SHALL 展示每名学生的学号、姓名、总分、提交时间、客户端标识与各题得分。
2. WHEN 教师导出成绩, THE 系统 SHALL 生成 UTF-8 CSV 文件，列至少包括学号、姓名、班级、总分、各题得分、提交时间。
3. WHEN 教师打开分析页, THE 系统 SHALL 计算并展示平均分、最高分、最低分、中位数、及格人数与及格率；及格线默认按满分的 60% 取整，教师可改为自定义整数及格线后重新计算。
4. WHEN 教师查看逐题分析, THE 系统 SHALL 展示每题正确率、平均得分率，以及各题型的平均得分率。
5. WHEN 教师查看分数段分布, THE 系统 SHALL 按满分把分数划分为 5 段（低于 60%、60% 到 70% 以下、70% 到 80% 以下、80% 到 90% 以下、90% 到 100%）并统计每段人数。
6. WHEN 教师打开成绩分析, THE 系统 SHALL 默认展示数据大屏（含优秀率、良好率、标准差、四分位、按班及格率），题目分析各大题汇总正确率、得分率与均分。

### Requirement 15: 教师端访问控制

**User Story:** AS 教师, I want 教师网页使用口令保护, so that 学生机浏览器打不开管理功能。

#### Acceptance Criteria

1. WHEN 教师首次启动服务且尚未设置口令, THE 系统 SHALL 要求设置教师口令后再开放教师网页的管理功能。
2. WHEN 访问者未通过教师口令校验, THE 系统 SHALL 拒绝教师管理接口，并仍允许学生进入已发布任务。
3. WHEN 教师修改口令且提供当前口令与新口令, THE 系统 SHALL 用新口令替换当前口令。

### Requirement 16: 教师监控与收卷控制

**User Story:** AS 教师, I want 在考试进行中看到提交进度并收卷, so that 可以掌握现场。

#### Acceptance Criteria

1. WHILE 考试任务已发布, THE 系统 SHALL 在教师网页展示名单内每名学生的状态：未进入、作答中、已提交。
2. WHEN 教师执行收卷, THE 系统 SHALL 对所有未提交学生使用已保存作答内容生成提交记录，并将任务切换为已收卷。
3. WHEN 教师在发布后修改「是否允许提前交卷」, THE 系统 SHALL 将新设置立即作用于尚未提交的学生网页。

### Requirement 17: 试卷模板

**User Story:** AS 教师, I want 先组可复用试卷再创建任务, so that 多场考试能共用同一套题量和分值。

#### Acceptance Criteria

1. WHEN 教师新建试卷并填写抽题规则, THE 系统 SHALL 保存试卷模板并计算分值方案。
2. WHEN 教师在试卷预览中修改某题分值, THE 系统 SHALL 更新该试卷总分与分值方案。
3. WHEN 教师创建任务并选择试卷, THE 系统 SHALL 复制该试卷的规则与分值，任务页不再提供调分。

### Requirement 18: 班级名册与任务名单

**User Story:** AS 教师, I want 按班级维护名册并为草稿任务勾选名单, so that 发布时名单已经冻结。

#### Acceptance Criteria

1. WHEN 教师创建班级并登记或导入学生, THE 系统 SHALL 按班级展示名册，支持本页多选删除。
2. WHEN 教师保存草稿任务名单, THE 系统 SHALL 用 200 返回更新后的名单。
3. WHEN 任务已发布, THE 系统 SHALL 拒绝修改名单。

### Requirement 19: 按班拆分子任务

**User Story:** AS 教师, I want 把覆盖多个班级的草稿按班拆开, so that 每个班有独立任务与入口。

#### Acceptance Criteria

1. WHEN 教师对多班草稿执行按班拆分, THE 系统 SHALL 为每个班生成子任务并删除原任务。
2. IF 任务已发布或只有一个班, THE 系统 SHALL 不提供拆分。

### Requirement 20: 讲台交互

**User Story:** AS 教师, I want 一屏看清列表与详情、用对话框看到结果, so that 教室操作不必来回翻页。

#### Acceptance Criteria

1. WHEN 教师点带详情的列表行, THE 系统 SHALL 选中该行并在右侧展示详情；删除控件出现在选中项标题栏。
2. WHEN 保存名单、发布、删除等需要确认的操作完成或失败, THE 系统 SHALL 用独立对话框提示。
3. WHEN 教师查看历史任务详情, THE 系统 SHALL 展示答卷入口。

### Requirement 21: 学生试卷分析选项

**User Story:** AS 学生, I want 公开后看到选择题的完整选项, so that 能对照自己的选择与正确答案。

#### Acceptance Criteria

1. WHEN 学生打开已公开任务的试卷分析, THE 系统 SHALL 为单选题与多选题列出各选项文本。
2. WHEN 选项被学生选中或属于参考答案, THE 系统 SHALL 分别标出「你的选择」与「正确答案」。

## Out of Scope

本阶段不包含：在线编译与测试用例评测、跨教室的中心化账号体系、手机 App、人脸识别、强制锁屏与远程桌面控制、题目图片与富文本公式编辑器、多教师协作与权限分级。
